## 1. 日常更新 dev

```bash
# 有新增 migration 時先套用（已套用過的會自動略過）
cd api && npm run db:migrate:dev

# build（prod 模式壓縮）＋ 部署
cd .. && npm run deploy:dev
```

部署後若首頁或 `/admin/` 短暫回 404 或舊內容，通常是剛生效的空窗，幾秒後重試即可。公開 API 有 60 秒邊緣快取，後台改的內容最慢約 1 分鐘出現在前台。

dev 後台管理員：`admin`（2026-11-06 建立，臨時密碼已交給業主，首登後請改）。忘記密碼見 §3 的重設指令。

## 2. prod 首次上線

### 2.1 建立資源並填回設定

```bash
npx wrangler d1 create paa-ur-db
npx wrangler kv namespace create paa-ur-kv-prod
npx wrangler r2 bucket create paa-ur-files
```

把輸出的 D1 `database_id` 與 KV `id` 填進 `api/wrangler.jsonc` 的 `env.prod`（取代全 0 佔位值），並更新檔頭註解與 `api/README.md` 的資源表。

### 2.2 套用 schema

```bash
npm run db:migrate:prod
```

會依序套用：

| migration | 內容 |
|---|---|
| `0001_init` | 資料表 |
| `0002_home_intro` | 首頁簡介的預設內容 |
| `0003_county_revision` | 頁面（計畫說明、補助辦法、申請流程、聯絡窗口）初稿、常見問答五類 26 題初稿、公告分類「宣導資訊」、檔案分類「說明會簡報」「宣傳手冊／摺頁」、線上諮詢設定、`inquiries` 資料表 |

`0003` 的頁面與問答內容取自說明會簡報與摺頁，**上線前需經縣府確認**（例如結構安全性能評估額度，摺頁與簡報數字不一致）。

### 2.3 內容：不要灌 demo seed

`seeds/0001_content.sql` 的公告、檔案、聯絡資訊、法律頁面都是**虛構示範資料**，不要套到 prod。prod 從空資料庫開始，部署後在後台建立：

| 後台模組 | 要做的事 |
|---|---|
| 設定 | 聯絡資訊（地址、電話、email）與服務時間，會顯示在頁尾與聯絡我們頁；LINE 加入好友連結、LINE ID、網路值班時段，會顯示在線上諮詢頁（LINE 連結留空時顯示「即將開放」） |
| 輪播 | 上傳主視覺海報（dev 用的裁切版在 dev R2 的 `hero/…-penghu-banner.jpg`，可從 dev 後台另存後再上傳）。**若換成不同的圖，OG 分享圖也要重做**（見 README「社群分享圖」） |
| 頁面 | 計畫說明、補助辦法、申請流程、聯絡窗口：migration 已帶入初稿，依縣府確認後的版本定稿 |
| 常見問答 | migration 已帶入初稿，依縣府確認後的版本定稿；上線後依諮詢內容持續增補 |

| 檔案 | 檔案分類：申請表單（公寓、透天住宅）、說明會簡報、宣傳手冊／摺頁、其他文件。上傳申請表單、說明會簡報 PDF、摺頁正反面與海報圖檔（dev 已上傳的原檔在 dev R2 的 `documents/` 下） |

### 2.4 建立 prod 管理員（臨時密碼）

```bash
PPW=$(openssl rand -hex 8)
PHASH=$(node scripts/hash-password.mjs "$PPW")
cat > /tmp/paa-ur-admin.sql <<EOF
INSERT INTO admin_users (username,password_hash,name,role,is_active)
VALUES ('admin','$PHASH','管理員','superadmin',1);
EOF
npx wrangler d1 execute paa-ur-db --remote --env prod --file=/tmp/paa-ur-admin.sql
rm -f /tmp/paa-ur-admin.sql
echo "PROD admin = admin / $PPW   ← 記下，首登後到右上角「變更密碼」修改"
```

### 2.5（建議）上線前閘門

內容還沒準備好之前，可以讓 prod 全站要求帳密，避免半成品被看到或被搜尋引擎收錄：

```bash
npx wrangler secret put BASIC_AUTH_USER --env prod
npx wrangler secret put BASIC_AUTH_PASS --env prod
```

正式開放時把兩個 secret 刪掉即可，不需重新部署：

```bash
npx wrangler secret delete BASIC_AUTH_USER --env prod
npx wrangler secret delete BASIC_AUTH_PASS --env prod
```

### 2.6 部署

```bash
cd .. && npm run deploy:prod
```

## 3. 驗證

```bash
B=https://<prod 網址>      # dev：https://paa-ur-dev.paa-612.workers.dev
curl -s -o /dev/null -w "front %{http_code}\n" "$B/"
curl -s "$B/api/health"; echo                 # env 應為 prod（dev 為 dev）
curl -s "$B/api/home" | head -c 300; echo     # hero、intro
curl -s -o /dev/null -w "admin %{http_code}\n" "$B/admin/"
curl -s -D - -o /dev/null "$B/" | grep -i robots   # dev 應有 noindex；prod 不應有
```

人工檢查：首頁主視覺與快速入口、計畫介紹三頁、最新公告、資料下載、常見問答（搜尋與展開）、線上諮詢、聯絡我們；公告內文與附件下載；後台各模組（含頁面、常見問答、設定）可登入維護。手機寬度也要看一次（主選單在 1020px 以下改為漢堡選單，站名較長會換行）。

社群分享預覽：把網址貼到 Facebook 分享偵錯工具或 LINE 對話，確認出現主視覺 OG 圖。

**重設管理員密碼**（忘記密碼時；dev 把 `paa-ur-db`／`prod` 換成 `paa-ur-db-dev`／`dev`）：

```bash
NEW=$(node scripts/hash-password.mjs '新密碼')
npx wrangler d1 execute paa-ur-db --remote --env prod \
  --command "UPDATE admin_users SET password_hash='$NEW', token_version=token_version+1 WHERE username='admin';"
```

## 4. 上線前後的安全性收尾

1. **Turnstile（登入人機驗證）**：目前未啟用。啟用要做兩件事：在 Cloudflare 建 widget（Hostnames 加入正式網域），把 site key 填進 `api/src/index.ts` 的 `TURNSTILE_SITE_KEY`；再 `npx wrangler secret put TURNSTILE_SECRET --env prod`。**順序很重要：先填 site key 並部署，再設 secret。** 後端只看 secret：有 secret 就要求驗證；若 site key 是空的，前台不會出現驗證元件，結果是**所有人都登不進後台**。
2. **Web Analytics**：⚠️ `web/index.html` 的 beacon token 目前**與 paa-web 相同**，paa-ur 的流量會算進 paa-web 的統計。請在 Cloudflare Web Analytics 為本站另建 site，換上新 token。
3. **CSP**：目前是 `Content-Security-Policy-Report-Only`（只回報不阻擋，違規記在 Worker 日誌的 `[CSP-Report]`）。觀察一段時間無誤後改為 `Content-Security-Policy`。**`api/src/index.ts` 與 `build.mjs` 的 `writeHeaders()` 兩處要同步改**，內容字串也要一致。
4. **管理員密碼**：dev、prod 的臨時密碼首登後都要改。
5. **線上提問表單（目前停用）**：若決定在本後台處理諮詢，把 `api/src/index.ts` 的 `INQUIRY_FORM_ENABLED` 改成 `true`、`web/admin/admin.js` 的 `MODULES` 加回 `['inquiries', '線上諮詢']`。表單的人機驗證沿用第 1 項的 Turnstile；新提問的 Email 通知尚未實作。
6. **備份**：有正式內容後即應建立。`npm run backup:prod`（D1 dump ＋ R2 鏡像，輸出到 repo 外的 `../paa-ur-backup/`），需要 rclone 與 R2 唯讀 token。腳本的資源名稱直接讀 `wrangler.jsonc`；操作步驟目前參考 `docs/備份與還原手冊.md`（該文件仍是 paa-web 版本，名稱需自行對換）。

## 5. 回滾

```bash
npx wrangler deployments list --name paa-ur-prod
npx wrangler rollback --name paa-ur-prod [version-id]
```

Worker 可即時回滾；D1 的資料變更不會跟著回滾（可用 D1 Time Travel：`npx wrangler d1 time-travel restore paa-ur-db --env prod --timestamp=<ISO 時間>`）。

## 6. 自訂網域

1. 決定網域（DNS 需由此 Cloudflare 帳號代管；`paa.org.tw` 已在帳號內，可用子網域，例如 `ur.paa.org.tw`）。
2. 在 `api/wrangler.jsonc` 的 `env.prod` 加上 `routes`（例：`[{ "pattern": "ur.paa.org.tw", "custom_domain": true }]`），重新 `npm run deploy:prod`。
3. 設了 routes 之後 `*.workers.dev` 預設會關閉，之後一律用正式網址測試。
4. 前台的 `/api`、`/files` 都是同源，換網域不需改程式；但 Turnstile 與 Web Analytics 的 Hostnames 要加入新網域。
