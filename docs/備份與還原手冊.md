# 備份與還原手冊

> **範圍**：正式環境（prod）的 D1 資料庫與 R2 檔案之備份、驗證與還原
> **建立日期**：2026-07-14
> **相關**：`api/scripts/backup.mjs`、`api/scripts/verify-backup.mjs`、`docs/雲端遷移可行性評估.md` 第七節

---

## 一、為什麼需要（Cloudflare 的內建機制不夠）

D1 內建 **Time Travel**（平台內的時間點還原），能救「誤刪一筆公告」。但它有三個救不了的情境：

1. **不涵蓋 R2**——附件、文件、相簿照片、會員照片目前在 R2 中是**唯一副本**，bucket 一旦誤刪即永久遺失。
2. **帳號層級的問題**——付款失敗、帳號爭議、服務條款變更時，平台內的備份會與平台一起失去。
3. **保留期外的還原**——例如三個月後才發現的資料錯誤。

Time Travel 是「平台內的還原機制」，不是「資料出口」。本手冊建立的是後者。

---

## 二、一次性設定

### 1. 安裝 rclone（R2 同步用）

```bash
brew install rclone
```

> Cloudflare 官方即以 rclone 作為 R2 的同步工具。wrangler CLI 只有 `r2 object get/put/delete`，**沒有 list**，因此無法單靠 wrangler 列舉整個 bucket。

### 2. 建立 R2 **唯讀** API token

Cloudflare 後台 → **R2** → **Manage R2 API Tokens** → **Create API Token**：

- Permissions：**Object Read only**（備份只需讀取；刻意不給寫入權限，避免備份腳本有能力破壞線上資料）
- Bucket：`paa-files`（正式）與 `paa-files-dev`（測試）

建立後取得 **Access Key ID** 與 **Secret Access Key**（Secret 只顯示一次）。

### 3. 設定環境變數

建立 `~/.paa-backup.env`（**不要放進 git**）：

```bash
export R2_ACCESS_KEY_ID="……"
export R2_SECRET_ACCESS_KEY="……"
```

```bash
chmod 600 ~/.paa-backup.env     # 僅自己可讀
```

使用前先載入：

```bash
source ~/.paa-backup.env
```

> Cloudflare Account ID 與 D1／R2 的資源名稱由腳本自 `api/wrangler.jsonc` 讀取，無需另行設定（單一事實來源，避免漂移）。

## 三、日常備份

```bash
cd api
source ~/.paa-backup.env
npm run backup:prod
```

> **prod 尚未部署期間**，先以 dev 演練整套流程（bucket 為 `paa-files-dev`）：
> ```bash
> npm run backup:dev
> npm run backup:verify:dev
> ```
> prod 上線並灌入真實會員資料後，**立即**改跑 `backup:prod` 並設定排程。

腳本會依序執行：

1. **前置檢查**——wrangler 登入狀態、rclone、R2 憑證（**全部檢查完才動手**，不會做到一半才失敗）
2. **D1 全量匯出**——`wrangler d1 export` 產生完整 SQL dump
3. **R2 鏡像同步**——rclone sync
4. **驗證**——**實際把 dump 還原進 SQLite**，並比對 D1 引用的檔案是否都在鏡像中
5. **寫入 manifest** 並清理逾期 dump（預設保留最近 30 份）

驗證未通過時**離開碼為 1**（排程可據此告警）。

### 產出結構

備份預設輸出到 **repo 之外**的 `../paa-backup/`（與 `paa-template/` 同層），避免含個資的備份被誤 commit：

```
paa-backup/
└─ prod/
   ├─ d1/
   │  └─ paa-db-20260714T0138Z.sql      ← 全量 dump（每次一份，保留 30 份）
   ├─ r2/
   │  ├─ current/                        ← 檔案鏡像（增量同步）
   │  └─ archive/20260714T0138Z/         ← 來源已刪除／覆寫的舊檔
   ├─ manifest-20260714T0138Z.json
   └─ latest.json
```

> **關於 `archive/`**：R2 同步採 `sync`（會反映刪除）搭配 `--backup-dir`，被刪除或覆寫的舊檔會移入 `archive/<時戳>/` 而非直接消失。因此**線上誤刪不會連帶讓備份失去該檔**——這正是備份要防的情境。

### 只備份資料庫（尚未裝 rclone 時）

```bash
npm run backup:prod -- --skip-r2
```

> 應急用。R2 的檔案是唯一副本，長期不備份風險極高，請儘快完成 rclone 設定。

## 四、還原演練（定期執行）

**未經驗證的備份不算備份。** 驗證腳本不是檢查檔案存不存在，而是**實際執行還原**：把 dump 灌進一個記憶體中的 SQLite 資料庫，語法損毀、內容被截斷或缺表都會在此爆炸。對線上環境**完全無副作用**。

```bash
cd api
npm run backup:verify:prod
```

輸出範例：

```
還原演練 — /Users/…/paa-backup/prod/d1/paa-db-20260714T0138Z.sql
備份時間：0.1 天前

  ✓ 還原成功：32 張表、407 列
  ✓ migration：5 筆，與 migrations/ 一致
  ✓ R2：鏡像 312 個檔案；D1 引用 42 個，其中 42 個在鏡像中

✓ 驗證通過——這份備份可以還原。
```

### 致命問題 vs 資料品質警告

驗證刻意把兩種結果分開——**若讓資料品質問題使備份失敗，備份就會永遠亮紅燈，而紅燈久了就沒人看。**

| 類型 | 意義 | 離開碼 |
| --- | --- | --- |
| **✗ issue（致命）** | **這份備份不可信**：dump 載不進 SQLite（截斷／損毀）、migration 落後、關鍵表全空 | **1** |
| **⚠ warning** | **備份是好的，但資料本身有問題**：例如 D1 指向不存在的檔案 | 0 |

檢查項目：

| 項目 | 類型 | 意義 |
| --- | --- | --- |
| **還原成功** | ✗ 致命 | dump 能被 SQLite 完整載入（可偵測截斷、損毀） |
| **migration 一致** | ✗ 致命 | dump 內的 `d1_migrations` 涵蓋 `migrations/` 下所有檔案；落後代表匯出自尚未套用 migration 的舊庫 |
| **關鍵表非空** | ✗ 致命 | `admin_users`、`members` 全空多半代表匯出到了錯的（或空的）資料庫 |
| **R2 交叉比對** | 見下 | D1 引用的檔案是否存在於鏡像 |

#### D1 路徑欄位的三種慣例

比對前必須先分辨清楚，否則會把不屬於 R2 的東西誤判為「備份缺檔」：

| DB 中的值 | 實際是什麼 | 由誰備份 |
| --- | --- | --- |
| `/files/portraits/001.jpg` | R2 物件（帶 `/files/` 前綴） | 本備份機制 |
| `attachments/abc-x.pdf` | R2 物件（裸 key；`/upload` 回傳的 `key` 直接入庫） | 本備份機制 |
| `assets/gallery/urban/01.jpg` | **前端靜態檔**（`web/assets/`，隨 `dist/` 出貨、由 ASSETS binding 服務） | **git** |

驗證腳本不靠前綴猜測，而是直接看該路徑在 `web/` 底下有沒有實體檔案——這對三種慣例都成立，日後新增前端資源目錄也不會失準。

#### R2 交叉比對的三種結果

- **在 `current/`** —— 正常。
- **在 `archive/`** —— 檔案已從線上刪除，但備份留有副本。**這代表備份正在發揮作用**，僅需知會。
- **兩者皆無（「懸空引用」）** —— D1 指向一個 R2 從來沒有的檔案。這是 **D1 的資料品質問題，不是備份缺陷**（鏡像不可能備份到不存在的東西），故列為 warning。

> **已知現象：seed 內容含 7 筆懸空引用。**
> `seeds/0001_content.sql` 灌入的示範公告帶有 7 筆附件紀錄（`seed/…pdf`），但對應檔案從未上傳至 R2（實測前台回 404）。
> 因此 dev（以及依 `上線部署手冊.md` §2 灌過 seed 的 prod）跑驗證時都會看到此警告。
> **這不是備份問題**，但意味著**前台這 7 個附件連結會 404** ——屬既有的內容缺口，需另行處理（補上檔案或刪除該些附件紀錄）。

> **維護提醒**：新增任何儲存 R2 路徑的欄位時，務必同步更新 `verify-backup.mjs` 的 `R2_REF_COLUMNS`，否則新檔案不會被納入驗證。目前涵蓋：`attachments.file_path`、`documents.file_path`、`photos.thumb_path`、`photos.full_path`、`members.photo_path`、`hero_slides.background_image`。

## 五、真正的還原（災難時）

### 情境 A：誤刪少量資料，且在 Time Travel 保留期內

**優先使用 D1 Time Travel**，最快且不需停機：

```bash
npx wrangler d1 time-travel restore paa-db --timestamp=<ISO8601>
```

### 情境 B：資料庫損毀／需從備份重建

D1 無法直接「覆蓋還原」，需建立新資料庫再切換：

```bash
# 1. 建新資料庫
npx wrangler d1 create paa-db-restored

# 2. 灌入 dump（用最近一次通過驗證的備份）
npx wrangler d1 execute paa-db-restored --remote \
  --file=../../paa-backup/prod/d1/paa-db-<時戳>.sql

# 3. 把 wrangler.jsonc 中 env.prod 的 database_id 換成新資料庫的 id

# 4. 部署
npm run deploy:prod
```

> **還原前務必先跑一次 `npm run backup:verify:prod`**，確認那份 dump 真的能還原。

### 情境 C：R2 檔案遺失

反向同步（本地鏡像 → R2）。**需要具備寫入權限的 API token**（日常備份用的是唯讀 token，刻意不給寫入）：

```bash
export RCLONE_CONFIG_R2_TYPE=s3
export RCLONE_CONFIG_R2_PROVIDER=Cloudflare
export RCLONE_CONFIG_R2_ACCESS_KEY_ID="<寫入權限 token>"
export RCLONE_CONFIG_R2_SECRET_ACCESS_KEY="<寫入權限 token>"
export RCLONE_CONFIG_R2_ENDPOINT="https://6125a621bf5bbd92935a668b987b8c66.r2.cloudflarestorage.com"
# ⚠️ 2026-08-04 帳號搬遷後：R2 API token（含日常備份用的唯讀 token）是綁 PLAY4FUN SERVICES
# 帳號建立的，換帳號後要到新帳號（PAA 澎湖縣建築師公會）Dashboard 重新建立一組，
# 上面 endpoint 也要對到新帳號 id（已更新為新值）。

# 先試跑，確認要傳的內容無誤
rclone copy ../../paa-backup/prod/r2/current R2:paa-files --dry-run

# 確認後實際執行（用 copy 而非 sync：只補檔案，不刪除線上既有物件）
rclone copy ../../paa-backup/prod/r2/current R2:paa-files --progress
```

> 此處刻意用 `copy` 而非 `sync`——`sync` 會刪除線上有但備份沒有的物件，在還原情境下極度危險。

## 六、排程

建立包裝腳本 `~/bin/paa-backup.sh`：

```bash
#!/bin/bash
source ~/.nvm/nvm.sh && nvm use default >/dev/null
source ~/.paa-backup.env
cd ~/project/paa-template/api && npm run backup:prod
```

```bash
chmod +x ~/bin/paa-backup.sh
```

加入 crontab（`crontab -e`）——每週一凌晨 3 點：

```
0 3 * * 1 ~/bin/paa-backup.sh >> ~/paa-backup.log 2>&1
```

驗證未通過時腳本離開碼為 1，會在 log 中留下 `✗` 記錄。**請定期查看 log**——沒有人看的排程等於沒有排程。

## 七、注意事項

- **備份含個資**（會員姓名、身分證字號、聯絡方式）。`.gitignore` 已排除備份目錄，但仍請注意：存放的磁碟應加密（macOS 開啟 FileVault），勿上傳至公開空間。
- **異地副本是必要的，不是選配。** 備份只存在本機，等同於「機器壞掉就一起沒了」。請將 `paa-backup/` 目錄同步至外接硬碟或雲端硬碟（Google Drive／iCloud 皆可）。
- **R2 備份用唯讀 token**——備份腳本不需要、也不應該有能力寫入或刪除線上檔案。
- **定期實際演練還原**（`npm run backup:verify:prod`），不要等到真的出事才第一次嘗試。
