PAA-UR · 系統架構

澎湖縣老宅延壽機能復新計畫｜技術架構

整個網站是一支 Cloudflare Worker：同一支程式同時提供前台頁面、後台管理介面與所有 API，資料分別放在 D1（資料庫）、KV（登入狀態）與 R2（上傳檔案）。dev 環境已部署，prod 環境的資源尚未建立。

整體架構

HTTP 請求／綁定存取 外部服務、排程觸發 D1 KV R2 ASSETS 邊緣快取

路由框右側的色塊，代表該路由會用到哪些綁定。手機上可左右滑動看完整張圖。

後台：登入與每次請求的驗證

  1. 登入 POST /api/admin/login
    先以 KV 計數做速率限制，再驗 Turnstile（有設 TURNSTILE_SECRET 才驗），最後以 PBKDF2 比對 admin_users.password_hash。
  2. 建立 session
    session 存在 KV，回傳 HttpOnly、Secure、SameSite=Strict 的 cookie。
  3. 後續請求進到 /api/admin/*
    非 GET 請求先做 Origin 同源檢查（CSRF 第二層防護），再由 cookie 取出 KV session。
  4. 回查資料庫
    帳號停用或改過密碼（token_version 不符）立即失效；角色一律以 DB 為準，降級即時生效。
  5. 滑動續期
    閒置 60 分鐘逾時，絕對上限 12 小時。
  6. 權限檢查與紀錄
    viewer 只能讀；寫入成功後寫一筆 audit_logs（含操作者、對象、變更內容、IP）。

資料表分組

公告

  • announcements：status 為 draft／scheduled／published／archived
  • announcement_categories
  • attachments：公告附件，檔案本體在 R2

檔案下載

  • documents：access 為 public／member
  • document_categories

首頁與站台設定

  • hero_slides、friend_links、home_sections
  • settings：key-value，存 home_intro、contact 等
  • legal_pages：privacy、terms

後台帳號與稽核

  • admin_users：角色、啟用、token_version
  • audit_logs：admin_user_id 為空代表排程自動發布

已建表、尚未接上

  • pages、menu_items：預留給下一階段的「頁面管理」
